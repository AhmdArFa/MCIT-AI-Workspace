# 🏛️ TuT AI (منصة توت للذكاء الاصطناعي السيادي)
## التقرير الفني الشامل: رحلة المشروع، التجارب، النتائج، وخارطة الطريق المستقبلية

## 1. المقدمة والرؤية العامة (Project Inception & Vision)

بدأ مشروع **TuT AI** (الذي تطور من النواة الأساسية لـ MCIT AI Workspace) بهدف بناء **منصة ذكاء اصطناعي سيادية، محلية بالكامل، ومستقلة 100% عن الخدمات السحابية الخارجية** لصالح وزارة الاتصالات وتكنولوجيا المعلومات المصرية (MCIT).

الرؤية تمحورت حول دمج 4 ركائز لم تكن تجتمع في منصة واحدة محلياً:
1. **دفاتر الأبحاث السيادية (Research Notebooks):** استيعاب مصادر المعرفة (PDFs, Docs, Web pages) مع تقنيات RAG واسترجاع ذكي دقيق يعتمد على اقتباس الفقرات بالأرقام.
2. **الوكيل الذكي المتعدد الخطوات (TuT Agent):** محرك وكلاء متطور يمتلك ذاكرة طويلة الأمد، أدوات تنفيذية (Tools & Skills)، ومجموعات عمل متعددة الوكلاء (Multi-Agent Groups).
3. **أستوديو الوثائق المعتمدة (Studio Engines):** توليد تقارير رسمية (Word / PDF)، عروض تقديمية (PowerPoint)، جداول بيانية (Excel)، وإنفوجرافيك بأسلوب الوزارة المعتمد مع حلقة تدقيق آلي (Self-Audit Loop).
4. **محرر المستندات المدمج (Integrated Office):** بيئة ONLYOFFICE كاملة داخل المنصة تتيح التعديل المباشر على المستندات المولدة وحفظها دون مغادرة النظام.

## 2. المسار التطويري وما تم اختباره (What Was Explored & Tested)

### أ. الهوية البصرية والسيادية (Egyptian Persona Convergence)
- **ما تم تجريبه:** بدأ النظام بهوية عامة مع بقايا علامات تجارية غربية (LobeHub). تم استبدال ذلك بالكامل ببناء منظومة **"الملك توت - TuT AI"**.
- **الابتكار المنفذ:** 
  - تصميم معرض متكامل من 10 شخصيات مصرية تاريخية وسيادية (توت عنخ آمون، أحمس، إمحوتب، حورس، تحوت، نفرتيتي...).
  - بناء البورتريه الهولوجرامي ثلاثي الأبعاد الشفاف (3D Transparent Holographic Portrait) مع إطار الخرطوشة الملكية المذهبة (`#D4AF37`)، وخلفية الأوبسيديان اللامعة (Midnight Obsidian Noir).

### ب. اختبارات نظام التصميم (Design System Shift & Safe Rollback)
- **التجربة:** تم اختبار التحول إلى حزمة تصميم جديدة خارجية (`C:\Users\abdoh\Downloads\design system`). ولكن أثناء تدخل أدوات أخرى حدث خلل وتلف في بعض مكونات واجهات العرض والـ Chat Input ومسارات التحويل.
- **القرار الحاسم:** تم اتخاذ قرار فوري بإجراء تراجع آمن (Safe Rollback) إلى نقطة التحقق المستقرة عبر فروع وتفرعات Git (`checkpoint-last-update` و `2aabdee7`) للحفاظ على استقرار النظام، ثم دمج أفضل التحسينات المطلوبة يدوياً بدون إفساد بنية الكود.
- **النتيجة المحققة في التصميم:**
  - تحويل نافذة أستوديو الوثائق (Studio Modal) من قائمة رأسية إلى **شبكة مربعة متناسقة 4-Cards Grid** (`grid-cols-2 sm:grid-cols-4`, `aspect-square`) مع خطوط ذهبية براقة وأيقونات معتمدة.
  - إلغاء صفحة البودكاست غير الضرورية وحذفها تماماً من القائمة الجانبية مع ضبط تحويل تلقائي (307 Redirect) إلى دفاتر الأبحاث (`/notebooks`).

### ج. معالجة وتحديات ذكاء الموديل وسرعته (Intelligence & Velocity)
- **المشكلة التي ظهرت:** الموديلات المحلية عند تشغيلها عبر الإعدادات الافتراضية كانت تعمل بنافذة سياق ضيقة (2k - 4k Tokens)، وبطء في زمن البدء (Cold-Start Latency)، وعدم قدرة على التفكير المعمق في المهام الإدارية المعقدة.
- **الحلول التي تم تثبيتها:**
  1. ترقية جداول قاعدة بيانات ParadeDB PostgreSQL (`ai_models` و `agents`) إلى **نافذة سياق عملاقة 131,072 Tokens**، و **16,384 Max Output Tokens**.
  2. تفعيل نمط التفكير المعمق **Reasoning Mode: `pro`** مع ميزانية تفكير **8,192 Thinking Budget** وفتح نمط الأدوات بالكامل `toolMode: "all"`.
  3. ربط الموديل بمحرك GPU مباشرة (NVIDIA RTX 4050) وتثبيت الموديل `gemma4:e4b` في الـ VRAM عبر أمر `keep_alive: "-1"` مما ألغى وقت إعادة التحميل وخفض زمن الاستجابة لأدنى حد ممكن.

### د. حل معضلة الـ Structured Output وتوقف الـ Agent
- **المشكلة:** عند إرسال ملفات أو محاولة استنتاج خطوات، كان محرك TRPC ينهار بسبب استدعاء دالة `this._runtime.generateObject` غير المدعومة بالكامل في الـ API الخاص بـ Ollama المحلي.
- **الحل النهائي:** تم كتابة محول التفافي ذكي (Smart Fallback Proxy) يقوم بفحص الطلب، وفي حال غياب الدالة يقوم بالتخاطب المباشر مع محرك Ollama، وتنظيف الـ Markdown Code Fences واستخراج كائنات الـ JSON بشكل سليم ومستمر دون أي توقف.

### هـ. إصلاح إرفاق الملفات وقابلية تغيير الأفاتار (Avatars & Attachments)
- **الملفات:** إصلاح ربط الملفات المرفوعة في مربع الدردشة لتمريرها مع الـ Prompt إلى الـ LLM مباشرة ومسحها عبر MCP tools.
- **الأفاتارات:** تم إزالة أمر `e.preventDefault()` الذي كان يمنع الضغط، وفرض صلاحية التعديل `canEdit: true`، وبناء شريط تبديل سريع بنقرة واحدة (1-Click Quick-Switcher) يغير الشخصية والأفاتار ورسالة الترحيب في كل واجهات المنصة دفعة واحدة.

## 4. خارطة الطريق للتطوير المستقبلي (Future Work & Enhancements)

1. **تسريع الاستدلال والسرعة القصوى (Inference Velocity & Fine-Tuning):**
   - دمج محرك `vLLM` لرفع سرعة التوليد إلى 60-80 توكن/ثانية.
   - تدريب LoRA Adapter مخصص للمستندات والخطابات الإدارية المصرية.
2. **الذكاء البصري المتعدد الوسائط (Vision & Multimodal Pipelines):**
   - دمج نماذج مثل `Qwen2-VL` لقراءة وتحليل الـ Scanned PDFs والمخططات الهندسية.
3. **منظومة سرب الوكلاء (Collaborative Multi-Agent Swarm):**
   - تفويض المهام المعقدة تلقائياً بين "تحوت" (للبحث والتدقيق) و"إمحوتب" (للبيانات والكود) و"توت" (للإدارة والتنسيق).
4. **تحسين البحث الدلالي والهجين (Advanced Hybrid RAG & Re-ranking):**
   - إضافة طبقة BGE-Reranker-v2-m3 لمنع أي هلوسة في التقارير الإدارية الحساسة.
5. **سجل الحاويات والتشغيل الآلي (Automated CI/CD & Image Registry):**
   - إعداد GitHub Actions لنشر صور الحاويات المسبقة البناء على GitHub Container Registry (`ghcr.io`).
